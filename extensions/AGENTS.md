# AGENTS.md

## Scope

Rules for the `extensions/` directory in this repository. These rules apply to the Pi TypeScript extensions stored here and do not replace the user's global `~/.pi/agent/AGENTS.md`.

## Inventory

Keep this table accurate when an extension is added, removed, renamed, or its user-visible behavior changes.

| File | Purpose |

| `plugin-manager.ts` | `/plugins` manages configured extension selections in All / Unselected / Selected / Settings; status is read-only and reload calls Pi's public reload. Uses native selection persistence and independent personal preferences; defaults to Default mode. Optional Auto adds eligible global tools with explicit activation contracts while respecting existing restrictions. See module and behavior notes below. |
| `auto-summary.ts` | `/summary` saves the latest text reply; `/summary [instructions]` generates versioned Markdown from bounded branch context. Generic `extension-usage` entries include the response provider/model, explicit USD currency, source/event identity and outcome. |
| `powershell-bash.ts` | Wraps `bash`, native `powershell` (kept opt-in via `defaultActive: false`) and `!` / `!!` through the same `powershell-bash/operations.ts` adapter and Pi public tool factories, with validated Core 7+, AST legacy-target checks, UTF-8 streaming and fail-fast cmdlet errors. Uses the shared process owner: ordinary Windows descendants remain in a kill-on-close Job until exited; direct WSL AST calls use client-tree cleanup. Timeout defaults to 120s; session shutdown joins active work. Public shell factories are wrapped by `powershell-bash/tools.ts` to add `execution` state, owner PID, elapsed time, output log and bounded-scope cleanup to native results, including timeout errors; aborted calls retain terminal session audit. | `tps-status.ts` | Publishes the latest completed assistant response's decode TPS in TUI mode via `ctx.ui.setStatus("tps", ...)`. Uses provider-reported `usage.output` only, with no character-count or `durationMs` fallback; live values are throttled to 400 ms and marked `~`. Aborted/error/deferred replies show no value. | `notify-dot.ts` | Completion marker on the terminal tab title: `agent_settled` (not aborted) prefixes a single marker plus one BEL **only when the user is not on this tab** — `●` normally, `✅` when the run included a context compaction, `❌` when the turn errored (compacted or not). Compaction never shows on its own: it only swaps the done glyph at the next settle, and only compactions during the run count (a manual `/compact` between turns does not; `session_compact_failed` is unhandled since its fallout surfaces as an errored turn). Blocking UI prompts wait visibly too (`ui_prompt_start`: kind `confirm` → 🔐, other kinds → ❓, dropped on `ui_prompt_end`; each prompt has its own generation guard so a late answer cannot restore an ended prompt, while independent completion probes remain valid); unseen markers keep priority ❌ > 🔐 > ❓ > ✅ > ●. `notify-dot/presence-probe.ts` resolves its script relative to the package module and owns foreground-probe subprocesses, per-session caching, deduplication, and invalidation so stale child results cannot refill the cache; simulated async answers are generation-guarded too. Presence: a read-only stdin observer handles DECSET 1004 focus reports before the fullscreen TUI consumes them; split input chunks are supported, original bytes continue to Pi for its own focus/selection handling, and any surviving reports are stripped at extension input before the editor (reporting is enabled once per TUI lifecycle; observer removed on shutdown); otherwise `notify-dot/foreground-check.ps1` (async pwsh, 3 s cache, skipped outside Windows Terminal per `WT_SESSION`/`TERM_PROGRAM`, killed on shutdown) decides tab-level on Windows Terminal by window caption, then UIA selected tab matched on the ` - <session> - <cwd>` suffix, then a window-level ancestor check (known limit: two unnamed sessions in the same directory share one suffix — whichever tab is selected then reads as present, so the marker can be missed, never falsely shown); input younger than 3 s skips the probe and an 8 s keypress heuristic is the last resort. Current session context is refreshed on each event and its `sessionManager.getCwd()` feeds the title/probe suffix. The marker clears on focus-in, ordinary extension input, `before_agent_start`, `session_start`, and `session_shutdown`; a return to the tab clears automatically when focus reports arrive, including fullscreen mode, without polling or added probe processes. Kill switch `PI_NOTIFY_DOT=off|0|false`; `PI_NOTIFY_DOT_PROBE=present\|away\|unknown` simulates the probe; debug log via `PI_NOTIFY_DOT_DEBUG=1`. `/notifydiag` opens an opt-in focus diagnostic: observes raw stdin, the existing actual Pi StdinBuffer when accessible, and notify-dot input before focus stripping; records bounded JSONL metadata/counters without typed text, supports a one-shot 5-second simulated completion and manual 1004 rearm, and removes observers/timers on close or shutdown. Diagnostic logs include the accepted focus source (`stdin` or `extension`); a zero fullscreen extension count no longer prevents clearing. |
| `ai-rename.ts` | `/n` renames the session (and the tab title): with an argument sets it directly; without one, asks the session's own model for a short display name from a topic digest — every user message (whitespace-collapsed, 200-char cap, first 15 + last 15 past 30) plus the AI's first text reply (600-char cap), with slash-command invocations (including the triggering `/n` itself) filtered out — and cleans the answer (first line, quote/command-token/punctuation strip, 40-char surrogate-safe cap). Registered as `/n` because the builtin `/name` is dispatched by a hardcoded text match before extension commands and a colliding registration is skipped entirely — the explicit-argument path mirrors the builtin's exact semantics (setSessionName, normalization readback warning) since no routing API exists. Shares model selection, Pi `modelRegistry.streamSimple().result()` requests, text extraction, usage recording and pending-operation lifecycle with auto-summary through `shared/model-call.ts`; Pi resolves request-time auth, headers, baseUrl, provider-neutral options and virtual routing. Usage follows the response provider/model. One auxiliary request, no added automatic retries; failures report a notification. Blocks session/branch navigation while pending; aborted on `session_shutdown`. A named session also makes notify-dot's tab-title suffix unambiguous for same-directory sessions. |
| `permission-gate.ts` | Blocks credential file tools/searches and high-confidence shell access from both `bash` and native `powershell`; shares snapshot authorization with `run-script`. Late approval after cancellation is ignored; asked/decided audit entries keep source hashes, never raw commands. Template `.env` files remain allowed; heuristic policy, not a sandbox. |
| `web-search.ts` | DeepSeek web search/fetch (`web-search/client.ts` API client + retry, `web-search/render.ts` theme-slot rendering). Tools: `web_search` (count 1–10, site:/quotes/|/../.. syntax in query; model content = numbered `[score/authority] title — site · ISO date` + ≤600c summaries with troff cleanup + web_fetch hint; transcript box collapsed shows `1.7 ¶4` badges + 相对日期 + `↺ 同#N` mirror marks, ctrl+o expanded shows blocked layout with labeled `相关 x.xx/3 · 权威 x/4 · site · ISO（相对）` meta, success/warning/error score colors, authority ≥3 success, `┄` summary gutters) and `web_fetch` (URL validated http/https no-credentials; unescaped Markdown, 20k chars/page via `offset`, SPA/JSON limitations documented in the tool description). Both `readOnlyHint`+`openWorldHint`, `outputSchema`+`structuredContent` for codemode. `/websearch <query>` direct search overlay (TUI, no model round-trip; non-TUI notify), `/websearch fetch <n|url>` pulls the n-th result of the last direct search, `/websearch status` shows billed calls/cache hits/estimated cost. Client: 5元/1000成功次计费， 408/429/5xx exponential backoff×2, 402/4xx no-retry with friendly messages, session TTL search cache (10min, exact query+count) and page cache (exact URL) for free repeat hits/local pagination, each capped at 50 entries and about 16 MiB; `PI_WEBSEARCH_DAILY_LIMIT` gate (default 300, 0=off) resets on local calendar dates within the current process, reserves concurrent requests, releases failed/empty/cancelled reservations and allows free hits at the limit (restart resets; multiple processes do not share quota). Ordinary mirror identities preserve URL path/query, ignoring fragments; successful/error response bodies are limited to 4 MiB, strictly decoded as UTF-8 and structurally validated, credentials resolve personal `config/pi-extensions/.env.web-search` under Pi agent dir → legacy extension-folder `web-search/.env` → pi auth.json `deepseek` api_key (base_url/api_key fall back independently) via readStoredCredential (exposed as `credentialSource`; key never in logs/details/errors; corrupt store/file tolerated). Empty results, failures and cache hits are not billed. Each billed tool/direct-command operation writes exactly one explicit CNY `extension-usage` service expense; no token usage is fabricated. |
| `write-transforms.ts` | Owns native-compatible `read`/`edit`/`write`. Successful UTF-8 text reads record canonical paths, byte SHA-256 versions and actually displayed line ranges; images, failures, cancelled reads and overlong unshown lines earn no permission. `edit` requires a current partial/full read; overwriting with `write` requires full coverage (pagination accumulates), while new files use exclusive creation. Successful edits inherit the reading grade and reset partial ranges; writes make the resulting version fully known. Session start (including restore, fork and reload), tree navigation, successful compaction and shutdown clear the state; generation/revision guards discard late reads. Edit matches all blocks against the original version, prefers unique literal matches, then tolerates only CRLF/LF and ASCII trailing spaces/tabs; ambiguous, overlapping and unchanged results are refused. Native file queues serialize writes; strict decoding, a prewrite version/identity check and byte-for-byte readback protect in-place writes and link semantics without a cross-process atomic guarantee. Uncertain writes clear reading state and require a new read, with no rollback or retry. The ordered `TRANSFORMS` pipeline has no active transforms; final diff/patch describe the transformed bytes. Edit calls show only path/block count, final results use Pi's native diff renderer and standard success/error shell; no execution preview. Shell/script reads and writes are outside this guard. |

## Extension Rules

- Prefer the official Pi `ExtensionAPI`, `pi`, and `ctx` surfaces.
- Keep each extension focused on one user-visible behavior.
- Keep descriptions concrete: name the command, event, tool, environment variable, or visible result that is affected.
- Do not embed API keys, tokens, machine-specific absolute paths, or private service configuration in source files.
- Preserve UTF-8 text handling and Windows compatibility when changing `powershell-bash.ts`.
- Preserve versioned, non-overwriting Markdown writes when changing `auto-summary.ts`.
- Preserve provider-usage-only TPS calculation (no character-count or `durationMs` fallbacks) when changing `tps-status.ts`.
- Update this inventory and the root `README.md` when an extension's user-visible behavior changes.

## Validation

- Run the TypeScript check from an environment with Pi's type declarations installed.
- Reload Pi or restart it after installing or changing extensions.
- Manually verify `/summary` after changes to `auto-summary.ts`.
- Manually verify a normal shell command, timeout, and `PI_POWERSHELL_EXE` override after changes to `powershell-bash.ts`.
- Manually verify the `tps` status appears in the TUI after a completed reply, and shows no value for cancelled replies, after changes to `tps-status.ts`.

## Distribution and validation

- The runtime extension directory and this distribution repository remain separate projects. Do not relocate the author's runtime setup or replace unrelated local extensions.
- Preserve distribution adaptations when syncing: package-relative notification resources and personal search configuration outside the package checkout.
- The root `package.json` explicitly exposes ten extension entry points; helper modules and tests are not entry points.
- Keep host-provided Pi modules and typebox in peerDependencies; do not install or bundle another Pi runtime.
- Tests live beside the affected extension or in `tests/` for package integration. Run `tests/run.ps1 -PiPackageDir <installed Pi package directory>` using existing system tools; it checks types and registered offline tests without installing dependencies.
- Personal configuration is read-only during loading. No automatic migration, credential copying or changes to personal rule files.
